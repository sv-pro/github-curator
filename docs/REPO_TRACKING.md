# Repository Tracking

Git-native repository tracking for maintaining curation history over time.

## Overview

The tracking system leverages git itself to store and version curation evaluations. Each tracked repository is cloned locally and maintains:

- **CURATION.md**: Append-only evaluation history (machine-readable)
- **REVIEW.md**: Latest human-readable review (publication-ready)
- **Git commits + tags**: Full traceability of each evaluation

## Workflow

### 1. Start Tracking

Clone and initialize a repository for tracking:

```bash
curator track https://github.com/fastapi/fastapi
```

This creates:
- Local clone at `~/.github-curator/tracked/fastapi/fastapi/`
- New `curation` branch
- Initial CURATION.md and REVIEW.md files

### 2. Evaluate Over Time

Curate the repository with different themes:

```bash
# First evaluation
curator curate-tracked fastapi/fastapi "Modern async web frameworks"

# Later, after repo has evolved
curator curate-tracked fastapi/fastapi "Production-ready Python APIs"
```

Each evaluation:
- Pulls latest upstream changes
- Runs full metacognitive evaluation
- Appends to CURATION.md (timestamped entry)
- Overwrites REVIEW.md (latest narrative)
- Creates git commit + tag

### 3. View History

See evaluation timeline:

```bash
cd ~/.github-curator/tracked/fastapi/fastapi
git log --oneline
git tag -l
cat CURATION.md  # Full history
cat REVIEW.md    # Latest review
```

### 4. List Tracked Repos

```bash
curator list-tracked
```

Output:
```
📚 Tracked Repositories (3)

• fastapi/fastapi
  Path: /home/user/.github-curator/tracked/fastapi/fastapi
  Curations: 2
  Last updated: 2025-10-11 14:23 UTC

• pallets/flask
  Path: /home/user/.github-curator/tracked/pallets/flask
  Curations: 1
  Last updated: 2025-09-15 09:45 UTC
```

## Git Structure

Each tracked repository has:

```
~/.github-curator/tracked/
└── {org}/
    └── {repo}/
        ├── .git/              # Git repository
        ├── CURATION.md        # Evaluation history
        ├── REVIEW.md          # Latest review
        └── [original repo files...]
```

Branches:
- `main` or `master`: Upstream code (pulled from original repo)
- `curation`: Tracking branch (contains CURATION.md + REVIEW.md)

Tags:
- `curation-001-20251011`: First evaluation on 2025-10-11
- `curation-002-20251015`: Second evaluation on 2025-10-15
- etc.

## Use Cases

### Track Evolution

Evaluate the same repo multiple times to see how it improves:

```bash
# Initial evaluation
curator curate-tracked myorg/myrepo "Initial assessment"

# 3 months later
curator curate-tracked myorg/myrepo "Q2 re-evaluation"

# Compare in git
cd ~/.github-curator/tracked/myorg/myrepo
git diff curation-001-20250101 curation-002-20250401 -- CURATION.md
```

### Generate Review Posts

Export REVIEW.md for blog posts or documentation:

```bash
cd ~/.github-curator/tracked/fastapi/fastapi
cp REVIEW.md ~/blog/content/reviews/fastapi.md
```

### Build Knowledge Base

Track multiple repos in a category and generate comparative reviews:

```bash
curator track https://github.com/fastapi/fastapi
curator track https://github.com/pallets/flask
curator track https://github.com/django/django

curator curate-tracked fastapi/fastapi "Python web frameworks 2025"
curator curate-tracked pallets/flask "Python web frameworks 2025"
curator curate-tracked django/django "Python web frameworks 2025"

# All REVIEW.md files now have comparable evaluations
```

## Configuration

### Custom Storage Location

```bash
curator track https://github.com/org/repo --base-path ~/my-curated-repos
curator list-tracked --base-path ~/my-curated-repos
curator curate-tracked org/repo "theme" --base-path ~/my-curated-repos
```

### Local Clone Analysis

Use `--use-git-clone` for faster, more thorough analysis:

```bash
curator curate-tracked org/repo "theme" --use-git-clone
```

## Benefits

**Version Control**: Full git history of evaluations
**Traceability**: Each evaluation tagged with commit hash
**Diff-Friendly**: See how evaluations change over time
**Portable**: Share/sync tracked repos via git
**No Custom Storage**: Leverage git's efficient object storage
**Publication-Ready**: REVIEW.md files ready for blogs, docs, or social media

## Future Enhancements

- Bulk tracking: `curator track --from-file repos.txt`
- Automatic re-evaluation: `curator refresh-tracked --older-than 30d`
- Export aggregates: `curator export-reviews --theme "Python web" --format html`
- Git hooks: Auto-evaluate when upstream has significant changes
- Remote sync: Push `curation` branch to your own repo for backup
